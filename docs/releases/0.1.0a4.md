# VIPER 0.1.0a4

Install the release with:

```bash
python -m pip install "viper-provenance==0.1.0a4"
```

## Local cross-workspace inputs

A run in one local workspace can now use an artifact produced by another local
workspace on the same machine. `LocalFileRef` and
`LocalStageResultSnapshotRef` record the producer workspace's absolute path,
the relative store path, and a durable `store_id`. VIPER opens that named store
and checks the store identity before reading the content-derived revision.

Each `LocalArtifactStore` writes its identity to `.viper/store/.identity`.
Identity creation uses an atomic filesystem link, so concurrent publishers
retain one complete value.

The producer workspace must remain at its recorded absolute path. Use Hugging
Face or Viper Cloud storage for cross-machine execution or movable producers.

## Prior-run input materialization

`run_artifact()` now freezes `materialization: attempt_workspace`. Execution
writes the verified artifact beneath the consuming run's attempt directory and
passes that path to the stage through `context.inputs`. The declared `path`
preserves the input's filename and subpath; it is no longer a shared writable
destination for newly authored plans.

Records without the new field retain `materialization: declared_path`. This
keeps their saved invocation paths verifiable.

## Persistent verified-object cache

Run verification caches resolved remote files by SHA-256 beneath
`.viper/cache/verified-objects/`. VIPER checks both byte count and SHA-256 on
every cache hit. A corrupt entry is ignored, the recorded backend is queried,
and valid bytes replace the entry atomically. Files already held by the local
artifact store are read from that store and are not duplicated in this cache.

External Git references reuse locked checkouts beneath
`.viper/cache/git-checkouts/`. Before reading a file, VIPER checks the remote
URL and exact commit. An interrupted checkout missing its remote or fetched
commit is repaired under the checkout lock.

Both cache directories are disposable while no VIPER process is using the
workspace. Removing them affects retrieval time, not retained run evidence.

## Restoration and execution

- `execution.restore()` accepts several artifact selectors in one call and,
  when given an output directory, restores each artifact under its frozen
  output path.
- `execution.resolve_run_reference()` creates a public immutable reference for
  a local terminal run document.
- Stages may opt into declared file access. VIPER records Python-visible file
  operations, rejects undeclared Python-visible paths, and rejects subprocess
  launches from that stage mode.

## Incompatible protocol change

`workspace` and `store_id` are required fields on every local file and local
stage-snapshot reference. VIPER rejects records created before 0.1.0a4 that
omit either field. Regenerate those references by publishing or freezing the
run with 0.1.0a4.

## Validation

The release receipt records the exact source commit, CI run, distributions,
registry hashes, clean-install checks, and installed-package acceptance result.
