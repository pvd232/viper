# VIPER 0.1.0a4

Install the release with:

```bash
python -m pip install "viper-provenance==0.1.0a4"
```

## Local cross-workspace inputs

A run in one local workspace can now use an artifact produced by another local
workspace on the same machine. `LocalFileRef` and
`LocalStageResultSnapshotRef` record the producer workspace's absolute path,
the relative store path, and a durable `store_id`. VIPER opens that named store
and checks the store identity before reading the content-derived revision.

Each `LocalArtifactStore` writes its identity to `.viper/store/.identity`.
Identity creation uses an atomic filesystem link, so concurrent publishers
retain one complete value.

The producer workspace must remain at its recorded absolute path. Use Hugging
Face or Viper Cloud storage for cross-machine execution or movable producers.

## Incompatible protocol change

`workspace` and `store_id` are required fields on every local file and local
stage-snapshot reference. VIPER rejects records created before 0.1.0a4 that
omit either field. Regenerate those references by publishing or freezing the
run with 0.1.0a4.

## Validation

The release receipt records the exact source commit, CI run, distributions,
registry hashes, clean-install checks, and installed-package acceptance result.
