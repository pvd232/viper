# VIPER 0.1.0

Install the stable distribution with Python 3.11 or newer:

```bash
python -m pip install viper-provenance==0.1.0
```

For optional MCP and Google Cloud Storage support:

```bash
python -m pip install 'viper-provenance[mcp,gcs]==0.1.0'
```

## Verified reuse by default

Workspace stages default to `reuse="verified"`. VIPER skips a worker only when
the complete reuse key matches and the saved result verifies. Set
`reuse="never"` for fresh computation. Independent benchmark confirmation
still computes its own result. The [complete reuse program](../../examples/reuse.py)
restores fresh and reused outputs and compares their exact bytes.

Successful runs enter the local catalog automatically. Knowledge refresh
preserves indexed runs, measurements, benchmarks, and reuse candidates.
`Catalog.refresh()` remains the deliberate complete-index rebuild.

## Scientific journals and learned retrieval

Place `JOURNAL.md` in `experiments/<experiment_id>/`. Successful run completion
captures its exact Markdown bytes, parses author-labeled paragraphs, links
selected saved measurements, and encodes the original passage text with
Qwen/Qwen3-Embedding-0.6B at revision
`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`.

The encoder records loaded file hashes and numerical runtime settings.
Journal capture preserves author-written text and supplies structured retrieval.
Scientific review remains separate. Journal failure emits a warning after the
experiment is saved. Python, CLI, and execute-mode MCP publish edited notes using
already saved training results. `[journals].enabled = false` disables publication.
The [journal guide](../how-to/journals.md) and
[complete executable program](../../examples/journal_search.py) show actual usage.

## Artifact restoration and checkpoints

Quickstart and execution-policy examples restore declared artifacts before
reading them, including reused runs. New attempts detach read-only or
hard-linked output copies before writing, preserving immutable stored bytes.
Output paths reject symlinks into retained storage.

Generated workspaces save actual checkpoint state and reconstruct its values.
Replace generated stage templates with the project's
model implementation before executing a scientific experiment.

## Cloud storage and public interfaces

The release includes bounded Google Cloud Storage restores, verified local-to-cloud
promotion, shared file identity, and public graph-based test selection from the
[0.1.0a5 candidate](0.1.0a5.md). The [cloud guide](../how-to/cloud-storage.md),
[test-selection guide](../how-to/test-selection.md), and
[API reference](../reference/api.md) define their supported operations.

Schema versions remain independent of the package version. Stage documents use
schema version 2; the [versioning guide](../reference/versioning.md) describes
older-document compatibility and the changed reuse default.

## Release verification

The signed release tag identifies the exact successful CI run. Publication uses
that run's wheel and source archive, checks TestPyPI before PyPI, and verifies
registry hashes against the retained distributions. The
[release workflow](../../.github/workflows/release.yml) defines these checks.
