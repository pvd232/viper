# VIPER 0.2.0

This release combines complete run-graph publication, bounded verification
reuse, explicit snapshot reference names, and the worker autocast repair.

```bash
python -m pip install --upgrade 'viper-provenance==0.2.0'
```

## Compatibility

Import `StageResultSnapshotRef` from `viper.references`. The old
`viper.references.StageResultSnapshot` and `viper.evidence.StageSnapshot`
aliases are removed.

Local file and stage-result references remove `store_id`. Their
addresses use the workspace, store directory, content revision, and, for a
file, its path within the revision. Existing local records require conversion
before this reader can load them. Keep original records and their compatible
reader for historical replay. This release accepts the converted format exclusively.
The [import and address details](unreleased.md) describe each changed reference.
The [migration record](store-id-removal-20261018.md) describes the converted
catalogs and preservation of original publications and model pointers.

## Publication and verification

Run-graph publication discovers dependencies before upload, journals remote
writes, resumes interrupted transfers, bounds staging and cache use, and
compares the destination graph with the source. The retained RICO publication
contains 1,305 required payloads and four recovered model checkpoints with
exact prediction agreement. See the
[completion record](../../evidence/run-graph-republication-completion-20261018.json).

Prepared upload identities, bounded verification downloads, directory scans,
and benchmark verification are reused within their verified scopes. Metric
dependencies are hashed as streams. Cross-execution integrity checks and
independent benchmark confirmation remain in place.

## Training precision

The worker precision helper returns `nullcontext()` when framework
autocast is disabled. When enabled, it disables the weight cache so optimizer
updates remain visible to later forwards. Metric workers use their declared
backend. CPU and CUDA regressions cover updated weights, repeated backward
passes, and restoration of the caller's cache setting. See the
[autocast incident](../development/autocast-cache-incident.md).

## Validation and publication

Pyrefly is the sole Python type checker. The release workflow requires passing
CI for the signed tag's exact commit and publishes the distributions retained
by that run. TestPyPI verification and a clean installation precede PyPI
publication. The release receipt records the final commit, checks, hardware
acceptance, and distribution hashes after publication.
