## Repository and CI gates

A clean checkout of the tagged commit passed these commands with Python
3.14.6:

```bash
make check-fast
make check-integration
python -m pytest tests -q -m release
python -m build
python -m twine check dist/*
```

The fast gate reported 170 passing tests, 61 deselections, and 11 passing
subtests in 35.84 seconds. The integration gate reported 54 passing tests,
177 deselections, and 22 passing subtests in 239.38 seconds. The release gate
reported one passing generated-project test in 150.79 seconds. `twine` accepted
the wheel and source archive.

GitHub Actions run
[`32805636860`](https://github.com/pvd232/BioStats/actions/runs/32805636860)
passed for the tagged commit. Python 3.14 completed the fast, integration, and
release-candidate jobs. Python 3.11, 3.12, and 3.13 each completed the
compatibility job.

## Registry and installed-package gates

GitHub Actions run
[`32808318766`](https://github.com/pvd232/BioStats/actions/runs/32808318766)
built the tagged source and published the two files to TestPyPI. The workflow
verified their TestPyPI digests, installed the indexed wheel, imported every
public name, and read the capability response. Its generated-project step then
failed because the runner environment lacked `pytest`.

Commit `57ab46c2e789f3c0f477f2a8642d5d313c6c5db7` added `pytest` to that step and
added a recovery path for a signed-tag artifact. GitHub Actions run
[`32808743624`](https://github.com/pvd232/BioStats/actions/runs/32808743624)
passed the complete Python 3.11–3.14 CI matrix for that workflow change.

Recovery run
[`32808873126`](https://github.com/pvd232/BioStats/actions/runs/32808873126)
downloaded the original signed-tag artifacts. It matched those files against
TestPyPI, installed the TestPyPI wheel, and completed the generated-project
test. The protected `pypi` environment then required Peter Driscoll's approval
before publishing the recovered files to PyPI.

A separate clean Python 3.14 environment installed the public PyPI wheel,
imported VIPER from `site-packages`, read the capability response, and completed
the generated-project test in 132.68 seconds. The same test completed from the
TestPyPI wheel in 125.11 seconds.

PyPI and TestPyPI report the two SHA-256 values in the release-identity table.

## Live GCE gate

The exact public wheel with SHA-256
`7edbc6d36bf2d8226ddeab153411bfb531fbf79dd8d13979cc6fa2c188523fec`
ran on one `g2-standard-12` Spot VM with an NVIDIA L4. The VM came from machine
image `mantra-backup-blueprint`, ID `4030260845309136958`.

Python 3.14.5 imported VIPER from the wheel's `site-packages` directory. The
environment used PyTorch 2.13.0 with CUDA 13.0. Six live process and stage
checks passed in 73.63 seconds. The generated acquisition plan, five-stage
candidate, benchmark confirmation, and terminal verification passed in 282.71
seconds.

The first public-wheel VM was preempted after five live checks. The release gate
discarded that incomplete result. A replacement VM completed the full gate from its
initial state. The replacement VM and its 500 GB SSD were deleted after the
gate. The retained machine image remains ready.
