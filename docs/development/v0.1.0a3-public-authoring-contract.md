The [API reference](../reference/api.md) documents the current interface;

requirement dependencies and recorded checks. The
[release contract](v0.1.0a3-core-release.md) governs candidate validation and

## Configuration, outputs, and artifacts

A workspace subclasses a config base from [viper.config](../../src/viper/config.py)
and supplies an instance to `stage()`. VIPER validates the config before calling
the stage and supplies it through `StageContext.config`.

`StageOutputs`, `TrainOutputs`, and `EvalOutputs` declare output names and
relative paths. The running function writes through `context.outputs`.
Execution records the resulting files as artifacts; verification checks those
files against their recorded identities. The same output name connects the
declaration, runtime path, and completed artifact. The
[stage guide](../how-to/stages.md) contains complete examples and required outputs
for each stage kind.

Public examples import classes and functions from their defining modules.
[The CPU quickstart](../../examples/cpu_quickstart.py) supplies the complete
training function, loaders, output declarations, experiment, and execution call.

## Runtime validation and measurements

`StageContext` and `MetricContext` are frozen slotted dataclasses. Configuration and
persisted records remain Pydantic models. Workspace computation operates on
runtime values after config validation.

`MetricHandle.update()` changes the stateful metric's in-memory aggregate.
It must construct no Pydantic record and perform no durable write.
`MetricHandle.record()` computes a value and appends exactly one validated
`Measurement`. [Runtime-boundary tests](../../tests/test_runtime_boundary.py)
check update behavior, measurement construction, and saved record contents
separately.

`ResumeState` retains the validated checkpoint envelope, including optimizer
and DataLoader state. Release profiling must measure `model_dump()` and
`torch.save()` together and record elapsed time, peak host memory, total
checkpoint bytes, optimizer-state bytes, and DataLoader-state bytes.

## Acceptance

The [quickstart](../../examples/cpu_quickstart.py) must execute and verify a
training run. The [evaluation example](../../examples/evaluation.py) must consume
saved test data, write predictions, recompute RMSE, and confirm its benchmark.
A diagnostic stage must produce its declared report; a plan that feeds that
report into a later stage must fail verification.

From the repository root:

```bash
source .venv/bin/activate
python -m pytest -q tests/test_config_contract.py tests/test_output_contract.py tests/test_output_paths.py tests/test_diagnostic_stage.py tests/test_dispatch_migration.py tests/test_runtime_boundary.py tests/test_public_inventory.py tests/test_documentation.py
python -m pytest -q tests/test_readme_workflow.py
```

The final candidate must also pass the [release gates](v0.1.0a3-core-release.md#candidate-validation).
Record distribution hashes and the checks of those exact files in the
[release report](../releases/0.1.0a3.md). An earlier build's results do not certify
a rebuilt wheel.

## Scope

USearch acceleration, compatibility aliases, category analytics, and additional
stage kinds remain outside `0.1.0a3`. Public names and protocol fields follow
the current schemas; this contract contains no alternate declarations.
